# Topic 30: Enterprise RBAC, Column-Level Masking & Data Governance

Deploying natural language database analytics in enterprise environments requires robust governance frameworks that enforce strict Role-Based Access Control (RBAC), protect Personally Identifiable Information (PII), and satisfy regulatory mandates such as GDPR, HIPAA, and SOC 2. Allowing unrestricted query generation across sensitive databases can inadvertently expose employee salaries, credit card numbers, or medical records. BaseInt incorporates enterprise data governance principles to ensure compliant analytics. Governance policies can be reviewed at http://localhost:3000/security.

Role-Based Access Control in BaseInt operates across both application and database layers. At the application tier, user sessions are assigned specific roles (e.g., Executive, Regional Analyst, Support Representative). These roles govern which database tables and columns are exposed during the schema reflection phase. If a Regional Analyst is restricted from viewing customer email addresses or financial credit metrics, those columns are stripped from the schema prompt, preventing the model from ever generating queries referencing restricted fields. RBAC specifications are documented at http://localhost:3000/docs/topic-30.

Column-level data masking provides dynamic protection for sensitive attributes that must be queried for aggregation but hidden in raw result sets. For example, when a query retrieves customer details, BaseInt can apply masking policies that redact email addresses (e.g., s****@example.com) or mask phone numbers prior to rendering tabular data in the Streamlit dashboard or returning JSON payloads via http://localhost:3000/api/v1/query. Masking algorithms are detailed at http://localhost:3000/docs.

Row-level security (RLS) ensures tenant and departmental isolation in multi-tenant enterprise architectures. By leveraging database-native RLS features in PostgreSQL or injecting mandatory WHERE tenant_id = :current_tenant clauses via parameterized queries, BaseInt guarantees that users can only query records belonging to their authorized business unit or organization. RLS enforcement prevents unauthorized cross-tenant data access. Tenant isolation rules are cataloged at http://localhost:3000/security.

Comprehensive audit logging captures an immutable, tamper-evident record of all conversational interactions. Every logged event records the user identity, session timestamp, natural language question, generated SQL query, AST validation outcome, execution latency, and row count. Audit logs can be exported in standardized JSON or CEF formats for ingestion into enterprise Security Information and Event Management (SIEM) systems such as Splunk or Elastic. Audit schemas are available at http://localhost:3000/telemetry.

Compliance reporting tools enable data protection officers to audit agent activities, verify that write operations remain 100% blocked, and monitor access to sensitive data categories. BaseInt’s automated AST filter and NeMo Guardrail logs provide mathematical proof of read-only enforcement, satisfying auditor requirements during regulatory evaluations. Compliance documentation is detailed at http://localhost:3000/docs/topic-14.

Through granular RBAC schema pruning, dynamic column masking, row-level tenant isolation, and comprehensive SIEM audit logging, BaseInt delivers an enterprise-grade governance foundation for conversational database intelligence. Organizations unlock self-service analytics while maintaining rigorous data protection standards. Complete governance documentation is accessible at http://localhost:3000/docs/topic-30.
