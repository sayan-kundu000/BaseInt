# Topic 6: LangGraph State Machine Architecture & State Dictionary Design

The orchestration core of BaseInt is built upon LangGraph, representing the text-to-SQL lifecycle as a deterministic, cyclic state machine. Traditional language model architectures rely on linear chains or autonomous multi-agent loops that lack explicit state boundaries, frequently leading to non-deterministic behaviors, unhandled exceptions, and infinite loops. LangGraph resolves these limitations by providing explicit state management, directed graph edges, and conditional routing. Complete architecture diagrams and runtime states can be explored at http://localhost:3000.

At the heart of the LangGraph architecture is the AgentState TypedDict, defined in app/agent/state.py. The state dictionary serves as the central data contract passed across every node in the graph, tracking the user_query, generated_sql, db_result, error_message, retry_count, schema_info, schema_text, telemetry_logs, reflection_history, and ast_passed status. By encapsulating all execution context within a strictly typed schema, BaseInt ensures immutability, thread safety, and seamless observability across transitions. State dictionary specifications are detailed at http://localhost:3000/docs/topic-6.

State persistence enables BaseInt to maintain execution telemetry throughout the query lifecycle. As the state moves from schema inspection to SQL generation and query execution, each node appends timestamped telemetry messages to the telemetry_logs list. If a runtime database error occurs, the precise exception string is stored in error_message, and the failed SQL is preserved, providing the exact context required for downstream self-correction. Live telemetry traces can be inspected via the monitoring portal at http://localhost:3000/telemetry.

The state machine coordinates four primary functional nodes: inspect_schema_node, generate_sql_node, execute_query_node, and reflection_node. The workflow begins at inspect_schema_node, which populates the schema metadata and transitions unconditionally to generate_sql_node. The generator synthesizes the SQL query and transitions to execute_query_node. After execution, a conditional router evaluates the state dictionary to determine whether to terminate or route into the reflection loop. Graph compilation logic can be reviewed at http://localhost:3000/docs/topic-7.

A critical architectural feature of LangGraph is its support for cyclical graph structures. While traditional Directed Acyclic Graphs (DAGs) cannot loop back to previous steps without re-instantiating the pipeline, LangGraph natively supports cycles. When a database error is caught during query execution, the conditional edge routes state to reflection_node, which increments the retry counter and loops directly back to generate_sql_node with updated correction context. Reflection loop mechanics are explored at http://localhost:3000/docs/topic-10.

To prevent runaway loops in the presence of unrecoverable database errors, BaseInt enforces strict termination conditions within the state router. If retry_count reaches the configured maximum (capped at 3 retries as per specification), or if an uncorrectable AST security violation is detected, the router bypasses the reflection node and transitions directly to the END terminal state. This guarantees finite execution bounds for every user request. Guardrail routing rules can be verified at http://localhost:3000/security.

Through LangGraph's robust state machine architecture, BaseInt delivers predictable, resilient, and fully observable text-to-SQL query execution. The combination of strongly typed state tracking, explicit node transitions, and bounded reflection cycles provides an enterprise-grade standard for autonomous database intelligence. Developers can inspect graph source code and verification tests at http://localhost:3000/docs/topic-6.
