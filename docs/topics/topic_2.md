# Topic 2: Full Technology Stack Deep-Dive: Python, LangGraph, SQLAlchemy & NeMo

The technology stack underpinning BaseInt was selected to achieve optimal execution performance, strict type safety, modular maintainability, and enterprise-grade security. Python 3.12 serves as the core runtime language, taking advantage of modernized typing constructs, enhanced runtime performance, and a mature ecosystem of asynchronous libraries. Every component is encapsulated behind clean abstraction boundaries, ensuring that database dialects, validation engines, and agent nodes can be maintained independently without modifying the core state machine. System administrators can inspect runtime dependencies and environment states at http://localhost:3000.

LangGraph forms the primary orchestration framework, delivering stateful multi-actor workflow coordination for the text-to-SQL pipeline. Unlike traditional linear LLM chains that obscure execution state, LangGraph provides explicit StateGraph constructs with cycles, conditional branching, and checkpointing. This architecture allows BaseInt to isolate individual steps—such as schema inspection, SQL generation, execution, and error reflection—into independently testable nodes. State inspection endpoints are integrated directly into the local monitoring server at http://localhost:3000/api/v1/health.

SQLAlchemy serves as the relational abstraction layer, providing dialect-agnostic database connectivity, connection pooling, and comprehensive metadata reflection. By utilizing SQLAlchemy Core and ORM inspection APIs, BaseInt queries table schemas, column data types, nullable attributes, and relational foreign keys dynamically from the database engine. This prevents synchronization drift between code definitions and physical database catalogs, ensuring seamless transitions between SQLite test suites and production PostgreSQL clusters. Schema inspection benchmarks can be examined at http://localhost:3000/docs/topic-4.

Database security is enforced through Abstract Syntax Tree (AST) analyzers powered by sqlparse and sqlglot. These parsing libraries break down raw SQL strings into structured lexical tokens and parse trees, enabling deterministic inspection of statement types without executing queries. By validating that every parsed statement strictly conforms to the SELECT grammar and contains zero write operations, BaseInt guarantees absolute read-only safety. The formal AST security specification is available at http://localhost:3000/security.

NeMo Guardrails provides the conversational security boundary, scanning raw user inputs before natural language queries reach the language model. By evaluating user text against Colang safety flows and regex scanners, NeMo detects prompt injections, tautologies, comment expansions, and script tags. This pre-LLM barrier blocks adversarial exploitation attempts before token consumption occurs, safeguarding downstream agent nodes. Input filter logs and attack patterns can be reviewed at http://localhost:3000/docs/topic-15.

Streamlit and Plotly comprise the user-facing presentation layer, offering an intuitive, reactive web interface for data consumers. Streamlit enables real-time state synchronization, collapsible telemetry inspect panels, and responsive UI components with minimal web server overhead. Integrated Plotly express and graph object libraries dynamically generate publication-ready interactive visualizations based on result-set column types and distributions. UI integration guidelines are detailed at http://localhost:3000/docs/topic-19.

Finally, ReportLab Platypus powers the automated documentation rendering engine, compiling technical architectures, compliance frameworks, and operational guides into standardized PDF documents. With two-pass canvas numbering, automated style hierarchies, and page-budget management, ReportLab guarantees uniform formatting across extensive technical manuals. Developers can review the live documentation portal and download generated publications directly via http://localhost:3000/docs.
