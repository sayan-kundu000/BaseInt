# Topic 8: LLM SQL Generation Node: Few-Shot Prompting & Temperature Control

The generate_sql_node serves as the cognitive engine of BaseInt, translating natural language user intent into precise, executable SQL syntax. The primary challenge in designing this node is ensuring that generated queries adhere strictly to database syntax, avoid speculative column hallucinations, and maintain zero write operations. BaseInt accomplishes this by combining structured system prompts, dynamic schema injection, few-shot demonstration heuristics, and zero-temperature inference controls. Real-time generation telemetry can be observed at http://localhost:3000.

System prompt engineering in app/agent/prompts.py establishes strict behavioral guardrails for the language model. The prompt explicitly instructs the LLM to act as an expert enterprise analytics agent, mandating that all outputs consist exclusively of raw, executable SQL with zero conversational preamble or markdown codeblock wrappers. Furthermore, the prompt enforces that only read-only SELECT statements may be generated, and all table and column references must match the supplied schema exactly. Prompt engineering specifications are detailed at http://localhost:3000/docs/topic-8.

Temperature control plays a critical role in stabilizing SQL generation. While creative writing tasks benefit from higher temperature settings (0.7 to 1.0) to encourage linguistic diversity, SQL generation requires strict mathematical determinism. BaseInt configures llm_temperature to 0.0, minimizing token sampling randomness and ensuring that identical user prompts produce consistent, deterministic SQL queries. Configuration options can be inspected via the settings manager at http://localhost:3000/api/v1/health.

Few-shot demonstration heuristics are dynamically incorporated to guide the model on complex analytical patterns, such as temporal date parsing, multi-table aggregations, and window functions. By exposing targeted examples of natural language queries mapped to optimized SQL syntax within the prompt context, the model learns the expected dialect conventions without fine-tuning overhead. Few-shot example libraries can be reviewed at http://localhost:3000/docs.

BaseInt incorporates dual-engine resilience within generate_sql_node to guarantee uninterrupted service during network outages or offline testing. When an OpenAI API key is configured, the node invokes gpt-4o-mini via modern ChatCompletions APIs. If an API key is omitted or external services are unreachable, the node smoothly falls back to an intelligent deterministic heuristic generator that handles standard analytics patterns, sorting requests, and error-recovery benchmarks. Offline generation capabilities can be tested at http://localhost:3000/api/v1/query.

Post-generation output cleaning is performed prior to updating the state dictionary. In some cases, language models wrap SQL code in triple backticks (```sql ... ```) or append conversational commentary. BaseInt’s _clean_sql_output utility strips extraneous markdown syntax and trailing whitespace, ensuring that downstream AST validators and database cursors receive clean, parseable SQL strings. Sanitization routines are documented at http://localhost:3000/docs/topic-8.

Through strict system prompting, zero-temperature controls, few-shot heuristics, and dual-engine fallback mechanisms, BaseInt achieves outstanding first-pass SQL generation accuracy. The node reliably converts ambiguous business questions into optimized relational queries ready for AST security verification and execution. Complete implementation details and benchmark results are accessible at http://localhost:3000/docs/topic-8.
